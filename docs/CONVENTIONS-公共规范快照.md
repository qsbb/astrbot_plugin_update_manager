# 凝心溯溪系列插件开发规范

 > **历史快照声明**：本文是公共规范 `astrbot/plugin/CONVENTIONS.md` 在 **2026-07-24** 的只读副本，仅用于历史追溯，不是当前实现规范，不应继续指导开发或验收。公共源文件 `../../CONVENTIONS.md` 是唯一现行规范；如两者不一致，以公共源文件为准。本文不得被视为、引用为或冒充一份独立规范。该快照早于情、核登记和 `/rel`、`/aup` 命令登记，缺少这些内容属于历史状态，不应据此删改现行清单。

本规范适用于 `astrbot/plugin/` 目录下所有属于"凝心溯溪"系列的 AstrBot 插件。新插件接入时必须遵循本规范，已有插件在下次版本迭代时应对齐。

---

## 1. 系列命名规范

### 1.1 系列名

**凝心溯溪**

所有属于本系列的插件在 `display_name`、`desc`、`short_desc` 中统一使用"凝心溯溪系列"作为前缀称呼。

### 1.2 展示名格式

```
凝心溯溪-{名称}
```

- **名称**：提炼插件核心功能的意象，风格统一、简洁可辨；原则上使用单个汉字。
- 名称不可重复，一经分配不可随意变更。

当前名称分配：

| 名称 | 插件目录名 | display_name | 取义 |
|------|-----------|--------------|------|
| 知 | astrbot_plugin_active_learner | 凝心溯溪-知 | 知识学习/检索/验证 |
| 言 | astrbot_plugin_conversation_flow | 凝心溯溪-言 | 对话 |
| 序 | astrbot_plugin_identity_guardian | 凝心溯溪-序 | 秩序/身份 |
| 声 | astrbot_plugin_voice_hub | 凝心溯溪-声 | 语音 |

新插件续接分配新的名称，需与已有名称不重复且风格一致。

### 1.3 内部标识（不可变）

以下标识**不随系列命名变动**，保持与仓库地址和配置映射一致：

- `metadata.yaml` 中的 `name` 字段（如 `astrbot_plugin_active_learner`）
- 插件目录名（如 `astrbot_plugin_active_learner/`）
- `@register` 第一个参数（插件唯一识别名）
- 用户命令名（如 `/memory`、`/convflow`、`/idg`）
- 配置文件名（`<plugin_name>_config.json`）和配置键名

### 1.4 描述文案风格

- `desc` 和 `short_desc` 以"凝心溯溪系列 XX 模块"开头。
- 功能描述用冒号分隔模块名和能力列表，如"凝心溯溪系列知识模块：知识学习、检索与验证……"。
- 不使用感叹号、不使用营销话术，保持工程文档语气。

## 2. 版本号规范

### 2.1 格式

统一采用语义化版本（Semantic Versioning），不带 `v` 前缀：

```
{主版本}.{次版本}.{修订号}
```

- **主版本**：不兼容的 API 变更（如命令名改名、配置键删除、钩子行为变更）。
- **次版本**：向下兼容的新功能（如新增子命令、新增配置项）。
- **修订号**：向下兼容的缺陷修复。

> 当前各插件版本存在历史不一致（四段式 `1.2.0.0`、带 `v` 前缀 `v0.3.2` 等），在下次发布时统一对齐为三段式无前缀格式。

### 2.2 当前版本与目标对齐版本

| 插件 | 当前版本 | 目标格式 |
|------|---------|---------|
| active_learner | 1.2.0.0 | 1.2.0 |
| conversation_flow | v0.3.2 | 0.3.2 |
| identity_guardian | v0.1.0 | 0.1.0 |
| voice_hub | v0.6.2 | 0.6.2 |

### 2.3 `astrbot_version` 声明

每个插件必须在 `metadata.yaml` 中声明 `astrbot_version`，使用 PEP 440 约束、不带 `v` 前缀：

```yaml
astrbot_version: ">=4.16,<5"
```

使用了特定版本 API 时，下界必须覆盖该 API 引入版本：

| API / 特性 | 最低版本 |
|-----------|---------|
| `on_llm_response` 钩子 | >=4.16 |
| `template_list` 配置类型 | >=4.10.4 |
| `file` 配置类型 | >=4.13.0 |
| `TextPart.mark_as_temp()` | >=4.24.0 |
| Agent / tool 新钩子 | >4.23.1 |

## 3. 事件钩子与优先级规范

### 3.1 优先级分配

多个插件共享同一钩子阶段时，必须显式声明 `priority`，不可依赖默认值或加载顺序。

约定优先级区间（数值越大越先执行）：

| 阶段 | 优先级区间 | 说明 |
|------|-----------|------|
| 普通消息监听 | 100-1000 | 按拦截紧急程度排列 |
| `on_llm_request` | 200-800 | 身份/安全注入先于知识/对话注入 |
| `on_llm_response` | 200-800 | |
| `on_decorating_result` | 200-800 | 文本分段（言）先于语音合成（声） |

### 3.2 传播控制

- 调用 `event.stop_event()` 后，后续插件的同类钩子不再执行。使用前必须确认是否需要截断整条链。
- 若只需阻止默认 LLM 流程但允许其他插件继续处理，优先使用 `event.stop_event()` 的替代方案（如设置 extra 标记），而非直接停止传播。
- `on_llm_request` / `on_llm_response` / `on_decorating_result` 钩子内不可 `yield` 消息；需要发送时使用 `await event.send(...)`。

### 3.3 已知顺序约束

以下执行顺序关系必须在配置文档或代码注释中标注：

1. **言（对话）的分段发送必须在声（语音）之前执行。** 若对话插件先分段并 `stop_event()`，语音插件不会执行；若语音插件先执行并加入音频组件，对话插件应跳过分段。当前两者均未设置 `on_decorating_result` 优先级，需在下次版本中显式分配。
2. **序（身份）的 LLM 注入应在知（知识）之前执行。** 身份边界属于安全层，应先于知识注入生效。

## 4. 命令命名规范

- 每个插件的命令使用独立前缀，不使用裸命令名，避免跨插件冲突。
- 前缀以 2-5 个字母组成，使用下划线或直接拼接。

当前命令前缀分配：

| 插件 | 命令前缀 | 示例 |
|------|---------|------|
| 知（知识学习/检索/验证） | `/memory` | `/memory list` |
| 言（对话） | `/convflow` | `/convflow status` |
| 序（身份） | `/idg` | `/idg status` |
| 声（语音） | 无聊天命令 | 通过 LLM 工具和配置触发 |

- 新增命令前缀前，需检查已有插件是否占用相同前缀或别名。
- 命令名不可包含空格；多级语义使用 `command_group`。

## 5. 配置规范

- 配置 Schema 文件命名为 `_conf_schema.json`，放在插件根目录。
- 每个字段必须声明 `type`，并提供 `description` 和 `default`。
- 配置键名使用全大写加下划线（如 `ENABLE_SHARE_PARSE`）或小写驼峰，在同一插件内保持一致。
- Schema 变更时遵循向后兼容原则：新增字段提供默认值；删除或重命名字段需在 `desc` 或 CHANGELOG 中标注迁移说明。
- 持久化数据存放在 AstrBot `data` 目录下，不存放在插件目录内。

---

## 6. 依赖规范

- 第三方 Python 依赖写入插件根目录的 `requirements.txt`。
- 网络请求使用异步客户端（`aiohttp`、`httpx`），不使用阻塞式 `requests`。
- 依赖版本约束使用 `>=` 下界，不锁定上限除非已知不兼容。
- 同系列插件共用的依赖（如 `aiohttp`）在各自 `requirements.txt` 中分别声明，不跨插件共享虚拟环境。

---

## 7. 测试规范

- 测试文件放在插件根目录的 `tests/` 目录下，文件名以 `test_` 开头。
- 每个插件至少覆盖核心路径：命令解析、配置加载、钩子入口逻辑。
- 测试不应依赖 AstrBot 运行时实例；对框架对象的依赖使用 mock 或 stub。
- 测试通过 `python -m pytest -q` 在插件目录下独立运行。

## 8. 文件结构规范

每个标准插件目录应包含：

```
astrbot_plugin_xxx/
├── main.py              # 入口文件，插件类继承 Star
├── metadata.yaml        # 元数据
├── _conf_schema.json    # 配置 Schema
├── requirements.txt     # 第三方依赖（无依赖时为空文件）
└── tests/               # 测试目录
    └── test_xxx.py
```

辅助模块按功能组织子目录或独立 `.py` 文件，不在 `main.py` 中堆积超过 1000 行。当前 `active_learner` 的 `main.py` 已超过此建议，后续迭代时应考虑拆分。

## 9. 热重载与卸载规范

- `terminate()` 必须清理所有运行时资源：定时任务、文件句柄、网络连接、动态注册的工具。
- 通过 `context.add_llm_tools()` 动态注册的工具，卸载时如有对应注销 API 则必须调用。
- 不应直接修改全局 `star_handlers_registry`；如必须操作，需在 `terminate()` 中以自身插件名为筛选条件，避免误删其他插件的 handler。
- 模块级单例（如 `_current_instance`）在 `terminate()` 中必须置空。
